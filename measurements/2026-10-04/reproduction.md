The measurements use native ModernFix code. Every arm starts at commit `aa3fff5971affbce1ca0501960158d41c11349b3`; each candidate contains only its own PR plus the same measurement hooks. Bons and Furious 1.0.26 remains in the frozen pack snapshot. That version predates these three downstream changes; their three properties are also set false in every arm.

To reproduce the method on another full pack:

1. Check out the base commit separately for baseline, #697, #698 and #699. Apply the matching `*-native-pr.diff` for each candidate, followed by its matching `*-instrumentation.diff`. The latter includes the two helper classes. Build the Forge jar with the repository's `reobfJar` task; our fixture builds used Java 21 with a Java 17 compilation toolchain.
2. Compile `SizeAgent.java` for Java 17 and package it in a jar whose manifest has `Premain-Class: bench.SizeAgent`. Launch every arm with `-javaagent:<that jar>`. This agent only supplies `Instrumentation.getObjectSize` for the set and its immediate backing arrays.
3. Keep the pack, resources, copied world, options, JVM and hardware identical. Replace only ModernFix between arms. Set ModernFix's stability level to `BETA` and explicitly enable `mixin.perf.compact_entity_models` in all arms. In our fixture, `faster_item_rendering`, `dynamic_languages`, `faster_capabilities.bytecode_analysis` and `ingredient_item_deduplication` are disabled in every arm.
4. Load the same copied world and perform three ordinary resource reloads through Minecraft's resource-reload future, with five seconds between completed reloads. The helper and mod-container timings are collected from the actual registered models and actual event dispatch, without repeatedly calling a synthetic handler. For the search path, open an installed tab that has its own search bar and type `stone` through the screen's normal `charTyped` handler. Our pack selects Botania's tab. The supplied probe diff shows the typed-input measurement; merely assigning the edit-box value does not reliably run this search path.
5. Read `MF_NATIVE` records. `helper_constructor` measures the entire `ModelBakeEventHelper` constructor. `bake_handler_*` measures one real `ModContainer.acceptEvent` dispatch, including empty dispatches. Allocation counts are bytes allocated on that dispatch thread, not all client threads. `set_storage` counts the set object and each directly referenced backing array once; shared model-location objects are excluded. Printing and the backing-storage inspection occur after the timed constructor/dispatch body. Hooks still add overhead and can influence JIT/GC scheduling.

The cube counter named `misses` counts invocations which take ModernFix's existing shared-cache path; it does **not** count misses in that existing cache. `hits` counts returns from the new per-definition memo. The render sample stores one boxed frame-time value per frame. It establishes natural invocation activity; the minimized/background rendering measurements are not used for an FPS claim.

Our whole-client heap samples follow `System.gc()` and a two-second delay. The GC counters advance in the captured samples, but heap differences include unrelated pack state and are not a precise retained-set measurement. The direct set/backing-array size measurements do not depend on a GC request.

The CSVs preserve every completed event, mod container, reload and replicate. A few `printf` timing records were interrupted by another logger. Their intact numeric continuations were joined without estimating missing values; `parser-recoveries.json` lists every reconstruction. Validation requires all 553 unique container dispatches for each of the two event types, at initial load and each reload, in every process.

The original pack snapshot and copied world are not included. These instructions reproduce the measurement method; a different pack will register different models and handlers. No whole-frame or whole-reload improvement should be inferred from the isolated helper or handler times.
